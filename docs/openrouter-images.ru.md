# Изображения через OpenRouter

Генерация подключается отдельно от разговорной модели. DeepSeek продолжает вести диалог,
а `generate_image` вызывает OpenRouter, сохраняет файл и отправляет его в текущий чат.

В защищённом серверном `.env` задать оба значения:

```dotenv
OPENROUTER_IMAGE_API_KEY=<секретный ключ OpenRouter>
OPENROUTER_IMAGE_MODEL=<точный идентификатор image-модели>
```

Эта пара имеет приоритет над прежними image-провайдерами. Частичная конфигурация
вызывает ошибку до платного запроса. Ключ не передаётся модели и не кладётся в workspace.
В installation Compose нужно передать обе переменные в сервис agent и пересоздать его.

Модель необходимо проверить через каталог `/api/v1/images/models`: она должна принимать
`aspect_ratio` (1:1, 3:2, 2:3). `size` выбирает пропорции, точное число пикселей определяет
провайдер. По умолчанию quality/background не отправляются; явные значения передаются
провайдеру, который может отклонить неподдерживаемый параметр. Прозрачность поддерживается
не всеми моделями. Редактирование по референсу этим инструментом пока не реализовано.

Внешние группы получают инструмент только после owner-подтверждения `generate_image`
через `manage_telegram_group.update_policy`. Сохранить остальные grants при обновлении.
Настройка не открывает личную/семейную память внешним группам.

Один вызов создаёт одно изображение. HTTP 4xx считается отказом. Таймаут, 5xx,
повреждённый ответ и неизвестный формат остаются неоднозначным исходом в durable ledger;
автоматического повторного запроса или перехода к другому провайдеру нет. Принимаются
только PNG/JPEG/WebP в ограниченном по размеру base64-ответе, внешние URL не скачиваются.

Порядок выпуска: canonical CI, установка его артефакта, настройка ключа/модели,
проверка одной картинки в личке, затем grant конкретным группам и проверка доставки.
Наличие кода и успешные unit-тесты не означают, что платный провайдер уже включён.

Документация API: https://openrouter.ai/docs/guides/overview/multimodal/image-generation

# История, память и личный профиль

История - журнал сообщений, полученных ботом после подключения. Память - отдельные
полезные факты, которые агент сохранил инструментом `remember`. Личный профиль -
отдельный механизм переноса подтверждённых сведений о человеке из группы.
Отключение последнего не отключает первые два. Сообщения до подключения не подгружаются
автоматически из Telegram, а наличие сообщения в истории не означает наличие memory claim.
