# Общие поручения и личный обзор

> Обновление исполнения, 10 сентября 2026: [действующий план завершения](family-completion-plan.ru.md).
> Выполненные работы D01–D09 отмечены отдельно; задачи W01–W24 различают код, сервер и приёмку.

Эта версия добавляет задачи поверх существующих областей personal, family и group.
Новая универсальная модель пространств и совместное монтирование файлов не вводятся.

## Как пользоваться

В подключённой группе можно попросить: «Предложи Анне заказать продукты до пятницы».
Бот выбирает исполнителя из проверенного каталога текущей области. Во внешней группе
кандидат должен уже написать боту в этой группе; перед назначением проверяется его текущее
участие в Telegram. Если имя неоднозначно, бот должен уточнить исполнителя.

Поручение другому человеку сначала имеет статус «предложено». Оно находится во входящих
исполнителя, но не считается принятым. Исполнитель может написать в группе или личке:
«Принимаю задачу заказать продукты». После этого она появляется среди принятых дел.
«Продукты заказаны, заверши задачу» меняет её статус; в исходной группе виден тот же статус.
Принять или завершить задачу за другого человека нельзя, включая владельца сервиса.

В личном чате «Покажи мои принятые задачи» собирает назначения текущему человеку из
личной, семейной и групповых областей данной установки. У каждой задачи указан источник.
«Покажи входящие предложения» отдельно показывает задачи, которые ещё не приняты.
Для личного чата нужно действующее подтверждённое членство в семье. Оно не требуется
обычному участнику внешней группы, который работает только внутри неё.

Срок задачи сам по себе не создаёт напоминание. С миграции 102 исполнитель может в личке
связать своё принятое дело с обычным напоминанием: `manage_reminder.create`, `taskId`,
`content` точно равен названию дела. Напоминание не завершает дело; завершение, отмена или
отказ останавливают будущие сигналы. Отправка, которая уже началась, может закончиться,
но следующий повтор не запускается. Уведомления о предложении и изменении статуса отдельно
в личку не отправляются: текущий ответ идёт в чат обращения.

Планировщик также хранит идеи и традиции без дедлайна и без назначения другим людям.
У записи есть имя списка, описание и версия. Исполнитель может изменить свою запись,
передав прочитанную версию; конфликтующие правки требуют повторного чтения. Идею можно
явно превратить в собственную задачу. Период личного плана отделён от общего срока и скрыт
из ответов в группе. Запись опыта традиции содержит автора, дату и его заметку, а не оценку
всей семьи. Практические сценарии описаны в [пилоте планировщика](family-planner-pilot.ru.md).

В личке «Найди договорённости по выходным во всех моих контекстах» использует
`search_my_contexts`. Инструмент ищет сохранённую память личной и семейной областей,
а также групп, где Telegram подтвердил текущее участие пользователя и действует право
`search_memories`. Он не выдаёт личную память других людей, файлы или полный архив сообщений.
Он не меняет права обычного `search_memories` и не разрешает редактировать из лички
групповые записи, найденные этим обзором.

Один вызов проверяет до десяти групп. `partial=true` означает, что результат неполный:
есть дополнительные группы, недоступные проверки членства или отозванные права.
Для конкретной группы используется проверяемый `groupRef` из списка доступных контекстов.
Ошибка Telegram не считается подтверждением членства. Telegram гарантирует работу
[`getChatMember`](https://core.telegram.org/bots/api#getchatmember) для других пользователей,
когда бот является администратором; без этого проверка может оказаться недоступной.

## Границы данных

- В группе список ограничен её областью. Личный обзор показывает назначения текущему
  человеку и запланированные им идеи/традиции; `view=waiting` отдельно показывает его
  просьбы другим. Предложение ещё не является принятым обязательством.
- Исполнитель и исходная область записи неизменны. Название, описание, список и срок
  меняет только исполнитель (для идеи/традиции — создатель). Автор просьбы не может
  переписать принятое другим человеком дело. Новое назначение требует нового предложения.
- С миграции 102 текст задачи может изменяться, поэтому личный обзор больше не сохраняет
  доступ к групповому поручению после выхода из группы: чтение и изменение заново проверяют
  текущее членство Telegram и право `manage_shared_tasks`. Ошибка проверки закрывает доступ.
  Уже доставленные сообщения остаются в истории Telegram. Удаление регистрации группы
  удаляет её задачи и связанные напоминания каскадно.
- Перед чтением групповой памяти проверяется актуальное членство Telegram; после поиска
  повторно проверяются членство, регистрация, семейная identity и право поиска.
  Уже доставленные в личный чат сведения не отзываются из истории этого чата.
- Ссылки на участников разрешаются сервером внутри точной области. Telegram/user/family ID
  и scope не принимаются от модели как полномочия.
- Повтор того же вызова задачи не создаёт вторую запись. Конкурирующие изменения
  сериализуются блокировкой строки, повтор с изменённым содержимым отклоняется.
- Списки выдаются страницами по 100 записей; `nextCursor` нужен для продолжения с теми же
  фильтрами. До десяти внешних групп проверяются за страницу; `incomplete=true` означает
  пропущенные данные, а не пустой список дел. Названия списков также собираются по страницам.
- Инструменты отсутствуют у subagent и в scheduled-ходах. У внешней группы задачи появляются
  только после явной выдачи capability `manage_shared_tasks` через штатное управление группой.

Для закрытого чата пары используется отдельная изолированная группа. Тип family_private
по-прежнему означает общую семейную область и не подходит для секретов пары от остальных
подтверждённых участников семьи. Права существующих групп эта миграция не меняет.

## Проверка и выпуск

Миграция 101 добавляет таблицы задач. Миграция 102 добавляет виды записей, личные периоды,
версии, историю традиций и необязательную связь напоминания с задачей. Идентичность старых
задач сохраняется; память не преобразуется, прежние напоминания остаются без связи с задачей.
Перед выпуском требуются тесты PostgreSQL, проверка типов, чистый npm ci на Node 24 и Eve build.
Production-сборка и миграция выполняются только штатным CI и установщиком.

После установки: выдать нужным внешним группам capability задач; проверить поручение от
одного реального участника другому, принятие в личке, статус в исходной группе и отказ
соседней группе. Для поиска проверить действующее и отозванное членство. Установка кода
сама по себе не является подтверждением этих живых сценариев.
