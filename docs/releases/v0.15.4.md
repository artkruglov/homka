# Osinara v0.15.4

Patch-релиз безопасного восстановления background memory review и уведомления владельца о блокировке.

## Восстановление очереди

- Ошибка подготовки до Eve handoff получает одну durable recovery-попытку. Этот retry безопасен:
  модель ещё не запускалась, а memory side effects невозможны.
- Любой failed или ambiguous результат после возможного запуска модели остаётся terminal, блокирует
  lane и не повторяется автоматически, чтобы не дублировать запись памяти или платный model call.
- Terminal batch больше не удаляет exact source references. Сообщения удерживаются для доказуемого
  операторского восстановления.
- Migration `068_memory_review_recovery.sql` восстанавливает существующий production batch только при
  полном retained source range, точной old session binding и отсутствии durable memory operation от
  прежнего Eve root. Старый root остаётся retired, а новый запуск получает свежую session.
- Каждая recovery-попытка записывается в `audit_events`; повторная автоматическая recovery запрещена.

## Уведомление владельца

- Blocking failure атомарно создаёт один durable outbox alert на batch.
- Minute schedule отправляет владельцу понятное private Telegram-сообщение с названием группы и
  диапазоном сообщений.
- Telegram delivery выполняется один раз. HTTP rejection фиксируется как failed, а сетевой outcome
  после возможной отправки как ambiguous; скрытых повторов нет.
- Текущий owner повторно определяется из PostgreSQL непосредственно перед delivery. Отсутствующий
  owner останавливает alert path с явной диагностикой, но не мешает независимой обработке review queue.

## Retrieval Eval

- Добавлен versioned V2 PostgreSQL/E5 benchmark на identity hard negatives: Осинара против Orca,
  Ива против Eve, repository против skill и source link против design link.
- Измеренный baseline: identity control recall@5 `1.0`, hard-negative empty rate `0.0`. Релиз явно
  фиксирует существующую проблему, но не меняет semantic threshold без отдельного согласованного этапа.
- Будущие semantic gating, reply-aware query context, history bounds и retention/archive policy
  описаны отдельно в `docs/memory-system-upgrade.md` и этим patch не реализуются.

## Проверка

- Migration integration test воспроизводит side-effect-free production recovery и запрещает requeue
  при наличии memory operation.
- PostgreSQL tests проверяют bounded retry, сохранение 50 source rows, owner outbox и one-shot delivery.
- Telegram transport и dispatcher покрыты unit tests для success, definite failure и ambiguity.
- Pinned E5 benchmark выполнен отдельно; полный Docker Compose gate прошёл migrations, typecheck,
  1704 теста и Eve build.
