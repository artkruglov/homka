# Osinara v0.11.0

Осинара получила полный production-контур долговременной памяти R0-R7: проверяемое происхождение
утверждений, изолированные профили, безопасную консолидацию конфликтов и продолжающиеся нити памяти.

## Безопасные ссылки и поиск

- Model-facing инструменты используют только opaque `memoryRef`; внутренние UUID, Telegram IDs и
  tenant identifiers не пересекают границу модели.
- Гибридный поиск объединяет Russian morphology FTS, точный multilingual FTS и multilingual E5,
  сохраняя жёсткую изоляцию personal, family и external-group scopes.
- Similarity используется только для отбора кандидатов. Она не даёт модели права автоматически
  объединять или удалять записи.
- Пагинация и source lookup повторно авторизуются по актуальным membership и group policy.

## Provenance и extraction

- Telegram timeline унифицирован для личных, семейных и внешних разговоров с durable cursor,
  immutable extraction snapshots и contiguous catch-up.
- Claims связываются с primary/supporting evidence и фактическим автором исходного сообщения, а не
  с пользователем, который вызвал агента.
- Sensitive candidates проходят identity-bound HITL до сохранения; plaintext snapshot удаляется
  только после terminal resolution всех кандидатов.
- Family-private сообщения исключаются до provider call, если автор больше не является участником
  семьи. Oversized entries получают terminal diagnostic и не блокируют последующие диапазоны.

## Профили и внешние группы

- Chat-local subjects формируют bounded profile views с воспроизводимым `profileViewRef`.
- Personal context может читать family claims о текущем пользователе без копирования исходной записи.
- External self-projection выключен по умолчанию и включается владельцем отдельно для каждой группы.
- Projection требует normal sensitivity, evidenced provenance, отсутствие inferred evidence,
  актуальное membership и подтверждённую доставку versioned notice.
- External group получает только собственные group-local memory и profile. Она никогда не получает
  personal/family memory или profile и никакие cross-group projections.

## Консолидация и конфликты

- Explicit и extracted claims проходят deterministic guards и durable semantic classification.
- Поддерживаются duplicate, refinement, temporal update, correction и conflict без destructive
  перезаписи исходного evidence.
- Исправление создаёт новую evidenced version, переносит thread membership и сохраняет предыдущую
  запись как историческую.
- Unresolved conflict возвращается только целиком: если одна сторона недоступна, скрываются обе.
- Sensitive/destructive операции исполняются только после exact HITL evidence для конкретного tool
  call и повторной проверки текущей роли.

## Нити памяти

- Добавлены root/subthreads, many-to-many entries, automatic discovery и source-backed live briefs.
- Completion фиксируется только подтверждённым outcome; завершённые эпизоды остаются доступны через
  thread tools, но не загружаются автоматически в каждый turn.
- Уведомления о новых нитях имеют durable delivery state. Неоднозначный crash после начала Telegram
  send терминален и не вызывает скрытую повторную отправку.

## Надёжность и production

- Новый `memory-extraction-worker` обрабатывает extraction, candidate resolution, consolidation,
  thread discovery и brief jobs вне Telegram request path.
- Provider calls и Telegram delivery имеют durable start markers; неоднозначные side effects не
  повторяются автоматически.
- Production Compose запускает worker только после migrations и healthy embedding service.
- Deployment controller проверяет exact resolved-Compose services, images, mounts, ports, logging и
  host capabilities тем же fail-closed predicate, который покрыт release contract tests.
- `nanoid` обновлён до безопасной transitive версии; dependency audit не содержит уязвимостей.

## Миграции

- `049_opaque_memory_refs.sql` добавляет opaque refs для существующих и новых memory items.
- `050_russian_memory_retrieval.sql` добавляет Russian morphology vector и индекс.
- `051_r2a_provenance_extraction_foundation.sql` создаёт conversations, evidence и extraction state.
- `052_r3_verified_profiles.sql` добавляет verified subjects, profiles, projections и approvals.
- `053_r4_r5_claim_consolidation.sql` добавляет lifecycle, relations, conflicts и consolidation jobs.
- `054_r6_r7_memory_threads.sql` добавляет outcomes, threads, entries, briefs и notices.
- `055_memory_reliability_barriers.sql` добавляет retention holds, terminal gaps и durable delivery
  barriers.
- `056_profile_projection_notice_delivery.sql` активирует projection только после подтверждённой
  доставки notice.

- TypeScript typecheck, runtime bundle, Eve production build и compiled manifest прошли без ошибок.
