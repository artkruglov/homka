# Osinara v0.14.4

Владельцы семьи снова могут читать и изменять файлы workspace во внешней Telegram-группе, которой
они управляют. Раньше корректный запрос владельца ошибочно завершался кодом
`AGENT_WORKSPACE_ACCESS_DENIED`, хотя группа и её workspace были зарегистрированы правильно.

## Доступ владельца к файлам группы

- Устранено противоречие между двумя независимыми ролями владельца: роль `owner` сохраняется во
  внешней группе для административных операций, но больше не блокирует обычные групповые файловые
  инструменты `glob`, `grep`, `read_file` и `write_file`.
- Доступ определяется trust zone текущей внешней группы, а не семейной административной ролью
  отправителя.
- Изоляция не ослаблена: каждый файловый вызов по-прежнему повторно проверяет точные `familyId` и
  `groupId`, тип `external`, групповой Telegram-контекст и актуальную регистрацию в PostgreSQL.
- Удалённая, перерегистрированная или сменившая тип группа по-прежнему немедленно теряет доступ к
  прежнему workspace.

## Проверка и deployment

- Добавлен PostgreSQL/filesystem integration-тест, воспроизводящий production-сценарий владельца
  семьи во внешней группе.
- Полный production-equivalent Docker gate проверяет миграции, TypeScript, unit и integration tests,
  а также сборку Eve.
- Production Compose graph, схема базы данных и root-owned deployment controller не изменяются.
- Release публикуется только из canonical `main` через GitHub Actions с immutable GHCR digests,
  attestations и exact release assets. Установка требует отдельного owner approval в личном
  Telegram-чате.
