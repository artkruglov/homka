# Osinara v0.19.0

Релиз делает переписку с агентом живее: ответ может прийти несколькими сообщениями, во время долгой
работы приходит короткая отбивка вместо молчания, а набор реакций берётся из настроек самого чата.
Отдельно расширено распознавание имени агента в группах.

## Живая подача ответа

- Один ответ может стать несколькими Telegram-сообщениями: сначала по делу, а через пару секунд
  отдельная мысль вдогонку, как это делают в живой переписке. Границу выбирает сама модель.
- Reply-цитата стоит только на первом сообщении; остальные приходят обычными репликами.
- Перед каждым следующим сообщением показывается индикатор набора текста, а пауза зависит от длины
  сообщения и не переживает время жизни индикатора Telegram.
- Ограничений на форму дополнительных сообщений нет: длина, абзацы, списки и разметка остаются
  решением модели. Приложение ограничивает только число сообщений с паузой, чтобы длинная серия не
  упёрлась в лимит частоты отправки Telegram и не оборвала доставку на середине.
- Правило сворачивания длинного ответа под раскрытие применяется к каждому сообщению отдельно.
- Служебная строка разделителя никогда не доходит до человека и не попадает в историю чата; внутри
  блока кода она остаётся обычным содержимым ответа.
- Запуски по расписанию не дробятся: отчёт приходит одним сообщением.

## Отбивки во время долгой работы

- Текст, который агент пишет перед вызовом инструмента, теперь доставляется человеку. До этого
  релиза он выбрасывался, и при долгой задаче чат молчал до готового результата.
- Отбивка отправляется не более одного раза на шаг: заявка в PostgreSQL делается до отправки,
  поэтому повторный проход того же хода не пришлёт её второй раз.
- Сбой отправки отбивки не прерывает ход: ответ, который она анонсирует, продолжает готовиться.
- Число отбивок на один ход ограничено, чтобы серия шагов не превратилась в поток сообщений.
- В историю чата отбивки не попадают и в запусках по расписанию не отправляются.

## Реакции по настройкам чата

- Раньше набор эмодзи для реакций был зафиксирован в промпте, и на выбор вне набора Telegram
  отвечал ошибкой: человек не видел ни реакции, ни текста.
- Теперь приложение раз в сутки на чат запрашивает список разрешённых реакций у Telegram и хранит
  его в PostgreSQL.
- Если чат разрешает все реакции, агент выбирает эмодзи свободно. Если администратор сузил список,
  агент получает ровно этот список. Если реакции выключены или список не удалось получить, агент
  отвечает текстом.
- Правила реакций переехали из постоянного ядра промпта в блок режима текущего чата: ядро стало
  короче на 2 199 символов, а в запусках по расписанию раздел реакций больше не выдаётся.
- В совсем новом чате реакции становятся доступны со второго обращения, потому что первый список
  запрашивается на первом ходу.

## Имя агента в группах

- Обращение по имени распознаётся с любым окончанием: `осинарочка`, `асинарачка`, `озинарка`,
  `осинарушка`, падежи множественного числа. Раньше набор окончаний был фиксированным, и на
  уменьшительную форму агент в группе не отвечал вообще.
- Совпадение внутри другого слова по-прежнему не считается обращением.

## Технические изменения

- Миграция `081_telegram_progress_notices.sql` добавляет барьер отправки отбивок по ключу
  eve-сессия, ход и номер шага модели.
- Миграция `082_telegram_chat_reaction_policies.sql` добавляет кэш разрешённых реакций чата.
- Тесты, проверявшие формулировки промптов, удалены: они фиксировали текст, а не поведение, и
  блокировали правки. Тесты логики резолверов промпта, discovery инструментов и доставки сохранены.
