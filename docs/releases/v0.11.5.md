# Osinara v0.11.5

Recovery release после post-migration health-gate отказа `v0.11.4` на исторической очереди memory
extraction.

## Причина patch-релиза

`v0.11.4` успешно проверил release, удалил legacy initial backup, создал и проверил единственный
новый rolling backup, остановил writers и применил migration `057`. Candidate services запустились,
но memory extraction worker не достиг stabilized health за десять минут.

Каждый provider failure уже атомарно переводил exact extraction job в terminal `failed`, после чего
worker повторно выбрасывал ту же ошибку на process boundary. Docker restart не повторял оплаченный job,
но исторический backlog содержал достаточно terminal failures, чтобы процесс постоянно перезапускался
и не прожил readiness stability window. Controller корректно записал proposal `v0.11.4` как
`ambiguous` и не promoted current symlink.

## Что исправлено

- После надёжной записи terminal provider failure worker возвращает successful handled-work result и
  продолжает следующий job в том же процессе. Повторного provider call для failed job нет.
- Unexpected ошибки до terminal repository boundary по-прежнему всплывают и останавливают process.
- Structured-output prompt требует точный корневой объект `{"candidates": [...]}` и явно запрещает
  одиночный action, корень `memories`, Markdown и внешний текст.
- Output budget увеличен до `16,384` токенов: schema допускает до 12 кандидатов с суммарным payload,
  который объективно не помещается в прежний лимит `4,096`.
- Readiness marker по-прежнему появляется только после successful durable pass и требует 30 секунд
  стабильного процесса.

## Состояние production

- Active symlink остаётся `v0.11.2`; edge и agent health доступны.
- Released `v0.11.4` migration `057` уже применена идемпотентно.
- Единственный rolling backup `20260808T123143Z-to-v0.11.4` сохранён и проверен.
- Memory extraction worker остановлен оператором после health-gate отказа, чтобы прекратить платные
  вызовы до установки исправления.

## Установка

- `v0.11.5` использует уже синхронизированный root-owned controller `v0.11.4`; service, mount и
  healthcheck allowlists не меняются.
- Новый immutable release требует отдельное owner approval; ambiguous proposal `v0.11.4` не
  переиспользуется.
- Deployment создаёт новый единственный rolling backup и запускает idempotent migration gate внутри
  released Compose graph.
- Promotion выполняется только после stabilized worker health и полного production health gate.
