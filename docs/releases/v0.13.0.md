# Osinara v0.13.0

Внешние Telegram-группы получают отдельное управляемое право на безопасное чтение текстовых
вложений. Файлы не загружаются автоматически, остаются изолированными в workspace точной группы и
никогда не открывают Bash или доступ к личным и семейным данным. Одновременно все режимы агента
получили единый fail-closed контракт против prompt injection внутри файлов.

## Текстовые вложения внешних групп

- Новая capability `import_telegram_attachment` по умолчанию выключена и появляется только в
  effective allowlist конкретной зарегистрированной external-группы.
- Владелец управляет правом из своего verified private Telegram-чата через существующий
  `manage_telegram_group`. Перед изменением агент обязан получить полный `status`, сохранить текущий
  allowlist и изменить только выбранное право.
- Durable ingress принимает metadata-candidate только при актуальном grant. После отзыва права новые
  документы отклоняются, старые ссылки не входят в turn context, а execution-time authorization
  блокирует импорт из уже открытой сессии.
- Поддерживаются только `.txt`, `.md`, `.json`, `.csv` и `.tsv`. Telegram MIME и имя файла считаются
  недоверенными metadata и не заменяют проверку фактических bytes.
- Lazy import повторно проверяет допустимое расширение, отсутствие определяемого binary type, strict
  UTF-8 и отсутствие NUL. PDF, DOCX, XLSX, HTML, XML, YAML, архивы, исполняемые и произвольные binary
  файлы остаются запрещены.
- Разрешённый файл сохраняется только в workspace точной группы. Tool возвращает canonical
  `/workspace/group/...` path, который сразу принимается защищённым `read_file`; относительный family
  contract не меняется.
- Поддерживаются вложения текущего сообщения и reply ancestry с exact chat binding. Cross-chat reply
  не может сослаться на файл другой группы.
- Ручной `list_group_history` фильтрует attachment metadata по актуальным media capabilities так же,
  как автоматический turn context; отзыв импорта или vision скрывает соответствующие старые refs.

## Защита от инструкций внутри файлов

- Постоянный trust hierarchy по-прежнему считает документы и tool results данными, а не системными
  инструкциями. Новый общий mode-scoped контракт применяется в private, family и external режимах.
- Если содержимое файла обращается к ИИ-агенту или модели, назначает роль и правила, требует забыть
  предыдущие инструкции, вызвать инструменты, раскрыть prompt, reasoning, секреты или внутреннее
  устройство, обработка этого файла немедленно прекращается.
- Подозрительный файл нельзя дочитывать, пересказывать, переводить, преобразовывать, исполнять,
  делегировать другому агенту, использовать для tool calls или сохранять в память.
- Пользователь получает один короткий русский отказ без цитирования вредоносного фрагмента и без
  раскрытия внутренних инструкций или защитных механизмов.
- Обычная документация, код и инструкции для человека не блокируются сами по себе, пока не пытаются
  управлять поведением агента или модели.

## Авторизация и изоляция

- Bash, network tools, personal/family mounts и другие запрещённые capabilities во внешней группе не
  выдаются вместе с импортом текстового файла.
- Dynamic tool surface строится из актуального режима и allowlist; отсутствие доказанного external
  registration или сбой resolver означает отсутствие application tools.
- Источником group identity и scope остаются verified Telegram update, session authorization и
  PostgreSQL. Модель не принимает group ID, роль или разрешение из текста сообщения либо файла.

## Проверка

- Unit tests покрывают классификацию расширений, binary magic, invalid UTF-8, NUL, materialization,
  current/reply refs, cross-chat rejection, capability-specific historical context и canonical path
  для guarded `read_file`.
- Database integration проверяет enabled/disabled durable ingress и live policy behavior.
- Prompt contract tests подтверждают fail-closed обработку agent-directed инструкций во всех трёх
  trust zones и сохранение запрета на раскрытие внутренних деталей.
- Production-equivalent Docker Compose gate, TypeScript typecheck, Eve build и `git diff --check`
  прошли; compiled manifest содержит `0` errors и `0` warnings.

## Production deployment

- Миграции базы данных, Compose graph, service/image/mount allowlist и root-owned deployment
  controller не менялись.
- Release публикуется только из canonical `main` через GitHub Actions с immutable GHCR digests,
  attestations и exact release assets.
- После публикации установка требует отдельного owner approval в привязанном личном Telegram-чате.
