# Osinara v0.18.0

Релиз переводит durable Eve Workflow на PostgreSQL, обновляет Eve до `0.40.0`, добавляет безопасные
операции над отдельными письмами Gmail и объединяет накопленные исправления Telegram, памяти и
sandbox egress поверх production `v0.17.1`.

## PostgreSQL Workflow

- Eve обновлена с `0.32.0` до закреплённой версии `0.40.0` вместе с совместимыми AI SDK и provider
  packages.
- Официальный `@workflow/world-postgres` хранит Eve sessions, tasks и durable waits в отдельной базе
  `osinara_workflow` внутри существующего PostgreSQL service вместо локального Workflow volume.
- Migration gate создаёт и bootstrap-ит Workflow database до запуска agent; отдельная роль получает
  только необходимые права, а обязательный пароль генерируется установщиком и хранится как secret.
- Одноразовый production bridge допускает только точный переход с `v0.17.1`: до Compose preflight он
  атомарно добавляет отдельный Workflow connection secret и строго проверяет его при повторной попытке.
- Deployment backup сохраняет логические dumps обеих PostgreSQL databases. Старый Eve `0.32.0`
  volume архивируется при cutover и остаётся доступен для явного rollback.
- Session retention удаляет завершённые Eve sessions через официальный PostgreSQL world adapter;
  отдельный stress harness проверяет параллельные turns, child tasks и retention.

## Gmail And Telegram Actions

- Новый `manage_gmail_message` изменяет состояние ровно одного письма по `messageId` и `profileRef`:
  read/unread, trash/untrash и необратимое delete.
- HITL показывает серверно прочитанные From, Subject и Date того же письма, которое будет изменено;
  после подтверждения executor повторно загружает письмо и отклоняет подмену identity.
- Произвольные mutating `gws gmail` команды закрыты: модель использует отдельный typed tool, а
  read-only Google Workspace path остаётся прежним.
- Telegram command routing, invitation codes и approval presentation получили строгую нормализацию
  входа и стабильные диагностические коды.

## Memory Recovery

- Background memory review materializes batches только для зарегистрированных Telegram groups и
  больше не создаёт невыполнимые personal batches.
- Migration `079_memory_review_source_binding_recovery.sql` безопасно переоткрывает только две точно
  проверенные group batches без side effects и восстанавливает их durable source ownership.
- Migration `080_remove_personal_memory_review_artifacts.sql` удаляет только подтверждённый ошибочный
  personal batch и две legacy lanes, сохраняя timeline, claims и evidence и записывая audit events.
- Task-origin auth возвращается из durable parent state при каждом wake, поэтому background work не
  теряет подтверждённую identity после restart.

## Sandbox Egress

- DNS resolver выбирает только публичный IPv4, соответствующий фактической Docker network без IPv6,
  и не переключается на заведомо недоступный AAAA address.
- 15-секундный CONNECT deadline действует только до TCP establishment и больше не разрывает рабочие
  idle tunnels.
- Закрытие client уничтожает orphan upstream, а нормальное закрытие upstream мягко завершает client
  после отправки буфера. Логи указывают фазу `request`, `resolution`, `connect` или `tunnel`.

## Проверка

- Чистый `npm ci` подтверждает version-pinned Eve `0.40.0` patches.
- Targeted contracts покрывают объединённые model limits, Gmail tool surface, approval timeout,
  migration order `077-080`, memory recovery и egress lifecycle.
- Полный Docker Compose gate проверяет unit/integration tests, PostgreSQL migrations, typecheck,
  Eve build, production tool discovery и runtime composition перед публикацией immutable release.
