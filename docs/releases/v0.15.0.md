# Osinara v0.15.0

Osinara обновлена с Eve `0.22.5` до `0.32.0`. Обновление переводит agent runtime, dynamic skills,
sandbox lifecycle, schedules и локальное Workflow storage на актуальные публичные контракты Eve,
не ослабляя границы личных, семейных и внешних групп.

## Eve 0.32

- Eve закреплена на точной версии `0.32.0`; AI SDK и providers обновлены до совместимых стабильных
  версий с единым `ai@7.0.60`.
- Удалены локальные patches, для которых Eve теперь предоставляет штатное поведение: AI SDK
  transport retries, queue namespace, root-only child delegation и изолированный HITL resume.
- Сохранены только необходимые version-pinned patches: durable Telegram ingress/drain, application
  routing и authenticated HITL callbacks, exact-once model policy, fail-closed approval persistence
  и увеличенный bounded startup health wait.
- Schedule delivery, Telegram continuation, HITL request kind и sandbox stop/shutdown переведены на
  публичные API Eve `0.32.0`.

## Clean Cut Сессий

- Старые Eve sessions и ожидающие HITL завершаются migration `065`; долговременная память,
  Telegram timeline, workspaces, группы, настройки и история schedules сохраняются.
- Уже начатые schedule, Eve dispatch или незавершённые voice provider calls переводятся в
  терминальный ambiguous/failed статус без автоматического повтора. Не начатые ingress updates и
  voice updates с уже сохранённым transcript безопасно возвращаются в очередь.
- Новый local Workflow world использует отдельный volume
  `osinara-production-eve-workflow-data-v032` в `/app/.eve/.workflow-data`.
- Deployment controller архивирует старый `osinara-production-workflow-data` до первого запуска Eve
  `0.32.0`, не монтирует его в candidate и удаляет exact legacy volume только после успешного health
  check и promotion. На следующих обновлениях архивируется новый active volume. Потеря
  current-owned volume остаётся fail-closed ошибкой deployment.
- Physical retention adapter обновлён под layout Eve `0.32.0`, включая durable waits.

## Dynamic Skills

- Grantable skills продолжают выдаваться нативным `defineDynamic` на `turn.started`; Eve materializes
  инструкции и supporting files в sandbox только для текущего разрешённого manifest.
- External `read_file` может читать supporting file только у видимого code-reviewed skill после
  повторной проверки актуальной регистрации группы и live allowlist. Произвольный `$HOME`, запись в
  skill package, а также `glob` и `grep` вне `/workspace/group` остаются запрещены.
- Skill, появившийся посреди turn, по нативному контракту Eve становится доступен не раньше
  следующего `turn.started`; отдельный runtime registry не добавлялся.

## Групповая память

- `remember` теперь может выбрать одно пользовательское сообщение из реально видимой дельты
  группового хода по его `#sequence`; в личном чате источником по-прежнему является только текущая
  реплика.
- Migration `067` добавляет durable memory-review lanes и batches. Каждые 50 пользовательских
  сообщений одной группы или Telegram-темы запускают один тихий root-agent turn без ограничения по
  символам и без Telegram delivery; ответы Осинары и другие темы в этот batch не входят.
- Неполный хвост до 50 сообщений прикрепляется к следующему обычному обращению. Cursor продвигается
  только после успешного terminal completion; failed/ambiguous batch не повторяется скрыто.
- Background review получает только инструменты чтения памяти и `remember`; Bash, web, файлы,
  skills, HITL и делегация перекрыты. Sensitive writes запрещены.
- Migration `066` сохраняет immutable allowlist источников для точного Eve session/turn. Backend
  повторно проверяет conversation, scope, partition, автора и видимость сообщения, поэтому модель не
  может сослаться на скрытую историю или другой чат.
- Source set временно удерживает выбранные timeline rows от pruning и переживает tool loop и
  ожидание HITL. Он удаляется после terminal completion/failure, когда evidence уже сохранён, но не
  удаляется при parked approval.
- Историческое сообщение сохраняется с identity его реального автора; инициатором mutation остаётся
  проверенный пользователь, который вызвал Осинару. Sensitive memory из дельты запрещена и требует
  текущего сообщения самого автора.
- Prompt создаёт нить только по сильному сигналу: явная просьба, продолжительная цель, будущие
  обновления, open loop, многошаговый проект или однозначное продолжение процесса. Одиночные эпизоды
  остаются обычными facts.
- Structured logs различают успешный/неуспешный `remember`, current/delta source и thread
  create/attach без записи memory content. Failed E5 jobs можно явно вернуть в durable очередь через
  существующую операторскую команду `npm run memory:reindex`.
