## Результат для семьи

Человек быстро записывает дело, видит свои обязательства из разных чатов, передаёт
ответственность с подтверждением и получает полезный сигнал вовремя. Ему не приходится
помнить, где обсуждали дело, пересылать его копии и постоянно напоминать другим.
Отправка уведомления не означает выполнения. Число закрытых задач не является рейтингом
вклада супругов. Список не должен превращать каждое желание в просроченный долг.

## Устройство

- Пространство задаёт аудиторию: личное, пара, семья, отдельная группа, работа.
  Публичность Telegram-чата и родство человека не заменяют права приложения.
- Список организует дела внутри пространства: покупки, дом, школа, поездка.
  Список не расширяет права пространства. Для другой аудитории нужно другое пространство.
- У задачи один постоянный ID, одно пространство, автор и не более одного принявшего
  исполнителя. Общая задача может сначала не иметь исполнителя: «кто возьмёт?».
- Личный обзор и список исходного чата показывают одну запись с общим статусом.
  «Мои дела» не копирует задачи в personal и не перемещает их из группы.
- «Сегодня» является личным представлением задач: выбор дня человеком не меняет общий
  срок и не создаёт новую задачу. Увидеть общую задачу не означает взять её на себя.
- У проекта есть результат и несколько действий. Область ответственности, например
  «школа», означает организацию результата согласившимся взрослым, а не вечное назначение
  всех её задач одному человеку. Эти расширения идут после полезного базового списка.

## Личный интерфейс и интерфейс группы

В личке доступны представления: «Входящие» (неразобранное и просьбы, двумя разделами),
«Сегодня», «Предстоящие», «Мои дела», «Жду от других», «Когда-нибудь», «Завершённые».
«Жду от других» содержит созданные мной просьбы в доступных пространствах, а не все
личные дела этих людей. Сейчас существующий личный list показывает только назначения мне;
для ожиданий автора требуется отдельная выборка.

В группе: именованные списки только её пространства, неназначенные дела, принятые дела
участников и запросы помощи. Фильтр «мои» сужает этот список, не подтягивает другие чаты.
У группы пары и общей семьи должны быть разные пространства и читатели.

Обычное создание и завершение собственного дела не требуют лишнего подтверждения.
Reply или кнопка с ID предпочтительнее угадывания по похожему названию. При двух подходящих
делах бот показывает короткий выбор. Исключение для закрытия (решение владельца 21 сентября 2026):
«закрой документы» закрывает все подходящие дела и перечисляет их, ошибочно закрытое
возвращается в работу одной фразой (`reopen`, история версий сохраняется). Пример ответа: «Добавлено в Покупки · Семья, без срока».

Пользователь из внешней группы сейчас может работать только внутри неё без членства семьи.
Для личного обзора внешних участников требуется отдельное подключение task-only identity:
оно не должно выдавать семейную память. В первой версии личный обзор остаётся доступным
подтверждённым семейным пользователям; ограничение явно показывается остальным.

## Договорённость, выполнение и время

Не смешивать состояние работы и состояние назначения. Работа: открыто / делаю / жду /
выполнено / отменено. Назначение: без исполнителя / предложено / принято / отклонено.
Отклонение предложения не уничтожает общее дело. Принятие не означает начала работы.
Переоткрытие сохраняет историю и не запускает прежние просроченные сигналы без новой политики.

Планируемый день, настоящий срок и время уведомления независимы. Срок может быть локальной
датой без точного часа или моментом с часовым поясом. План «сегодня» не превращается в
просрочку после полуночи. Все подтверждения показывают абсолютную дату и понятное время.

Предлагаемый контракт естественных фраз:

- «Запиши купить молоко» — задача без срока и сигнала.
- «Напомни завтра в 18 купить молоко» — задача и связанное уведомление, с явным ответом об обоих.
- «Только уведомление завтра в 18» — отдельное напоминание без задачи.
- «Нужно до пятницы» — настоящий срок, без выдуманного времени; сигналы по ранее настроенной
  политике человека, а если политики нет, бот прямо сообщает «напоминание не настроено».
- «Сделай сегодня» — план на день; точный обязательный срок уточняется только когда нужен.

Это изменение текущего поведения: сегодня просьба «напомни» создаёт только reminder.
Существующие reminders не превращать в задачи автоматически; связывать только выбранные
записи после дедупликации. Важный сигнал имеет ограниченные повторы по явной настройке;
никакой автоматической эскалации родственникам по молчанию.

## Редактирование, аудитория и членство

Исполнитель меняет свой план, рабочий статус и собственные уведомления. Автор и разрешённые
редакторы пространства меняют описание общего дела с историей версий. Существенное изменение
принятого результата или общего срока требует нового согласия исполнителя; прежняя версия
договорённости не исчезает молча. Редактор списка не получает права принять задачу за другого.
Изменения назначения проходят отдельный запрос передачи.

При публикации личного дела в другую аудиторию показывается точный публикуемый текст.
Общая запись не получает будущие личные комментарии. Связь и копирование через пространства
являются явным исключением из правила одной записи; синхронизация скрытого текста запрещена.

Для редактируемых задач нужно пересмотреть текущую пожизненную доступность назначения после
выхода из группы: новые версии и вложения требуют актуального членства. После выхода допустим
только архивный снимок уже принятого поручения с прежней аудиторией, без новых данных; активные
запросы и доставки приостанавливаются. До внедрения этого контракта старые неизменяемые задачи
не превращать в изменяемые. Уже полученные Telegram-сообщения не отзываются из истории.

## Надёжность и данные

Реестр задач в PostgreSQL является источником статусов, сроков и исполнителей. Память даёт
контекст, но не подменяет реестр: «запомни, что надо» не создаёт обязательство скрыто.
Поиск дел обращается к реестру, а не восстанавливает список из истории модели.

Создание/изменение задачи и планирование её уведомлений согласуются транзакционно через
журнал исходящих операций. До отправки проверяются версия, состояние, адресат и права.
Готовое текстовое напоминание доставляется без LLM. У доставки отдельные статусы и ошибки;
успех Telegram не означает прочтения или выполнения. После неоднозначного сетевого сбоя
нет слепого повтора. Для уже начавшейся отправки остаётся гонка с завершением задачи;
будущие сигналы отменяются, уже отправленный текст не объявляется отозванным.

Первая схема расширяет существующий модуль следующими миграциями: списки, версии задачи,
запросы назначения, личный план, связанные уведомления и журнал изменений. Полную старую
схему не возвращать: она не закрывала принятие поручений и новые границы чатов. Универсальные
space_id внедрять сквозным контрактом, а не столбцом только в tasks; до этого сохранять
ограничения personal/family/group и не обещать изоляцию между family_private-чатами.

## Порядок реализации

1. Полезный сквозной сценарий T01–T09: реестр, неназначенное/принятие, личные представления,
   редактирование с версиями и правами, связи с reminders, уведомления и видимость сбоев.
   Определить миграцию доступа до включения редактирования; сохранить существующие напоминания.
2. Покупки, повторы и передача ответственности T10–T12. Проверить конкурентные действия
   двух реальных пользователей, перенос времени и перезапуск между операциями.
3. Отдельные пространства пары/семьи с безопасной миграцией всех данных и подключение календаря.
   До расширения состава семьи пространство пары обязательно должно быть изолировано.
4. Проекты, области ответственности, помощь родственников и недельный обзор T13–T16;
   отдельный личный доступ внешних участников без расширения семейных прав.

Порог готовности первой версии: личное дело и поручение из группы видны в правильных списках;
получатель принимает сам; уведомление приходит после перезапуска; завершение останавливает
будущие сигналы; соседний чат не видит ни текст, ни название; два параллельных изменения
не теряются. Приёмка двумя реальными участниками обязательна, mock-проверок недостаточно.

без обязательств, личное время, согласованные ритуалы и добровольный обзор нагрузки.
Эти сценарии входят в продуктовую цель наряду с надёжной организацией бытовых дел.
